# tronc-rs — Development

How to build, test and release the crate, and how the Go test vectors stay in step.

## Prerequisites

- Rust 1.98 or later (`rust-version` in `Cargo.toml`), with `rustfmt` and `clippy`
- Docker, for the scratch Postgres the database tests use
- `filet` 0.18 or later, and `lefthook` through `mise install`

## Setup

```sh
mise install
mise run db-up
export TEST_DATABASE_URL='postgres://postgres:test@127.0.0.1:5651/postgres?sslmode=disable'
```

`db-up` starts `postgres:16-alpine` on `127.0.0.1:5651`. `mise run db-down` stops it.

## The gate

```sh
sh scripts/check.sh
```

It runs `cargo fmt --check`, `cargo clippy --all-targets --all-features --locked -- -D warnings`,
`cargo test --all-features --locked`, then `filet check .`. `mise run check` calls the same
script, and `lefthook` runs it on pre-push. Without `TEST_DATABASE_URL` the database tests print
a skip banner and pass, so read the output before trusting a green run.

Each feature must also build alone. Check a change to feature wiring with:

```sh
for f in http health spa migrate testdb journal apiref; do
  cargo clippy --all-targets --no-default-features --features "$f" -- -D warnings
done
```

## Tests

| File | Covers |
|---|---|
| `tests/conformance.rs` | Every case in `tests/vectors/*.json`, generated by Go `tronc` |
| `tests/example.rs` | Boots `examples/minimal.rs`, probes `/health`, the SPA and `healthcheck` |
| `tests/database.rs` | `migrate` and `testdb` against Postgres |
| `tests/journal.rs`, `tests/journal_layer.rs` | Journal wire format against a fake server |
| `tests/apiref.rs`, `tests/apiref_coverage.rs` | The `/docs` page, the document and the drift check |
| other `tests/*.rs` | Chain, CORS, rate limit, overrides, JSON, env, logger |

## Vectors

The vectors are Go `tronc`'s `conformance/vectors/*.json`. Every file has the envelope
`{"source","subject","cases":[{"name","input","want"}]}`. `tests/vectors/SOURCE` names the tag
they came from, and a test fails when a file names another.

```sh
sh scripts/sync-vectors.sh v0.20.1
sh scripts/sync-vectors.sh ~/Code/Facile/tronc-wt-vectors
```

The script takes a tag (it clones `FacileStudio/tronc`), a checkout, or a vectors directory.
After a sync, `git diff tests/vectors` shows what Go changed, and `cargo test --test
conformance` shows what the port must change. Fix the port, never the vector.

## Rules

- `#![deny(unused, dead_code)]` in the crate root, doc comments on every public item, no
  comments inside function bodies.
- filet's limits hold for every `.rs` file, tests included: 250 lines, 8 functions, 30-line
  functions, nesting 4. Split a module rather than raising a limit.
- New dependencies take the latest stable release; commit `Cargo.lock`.

## Versioning

Semver on `v0`: a breaking change bumps the minor. Consumers pin a git tag. Record every change
in `CHANGELOG.md` under `[Unreleased]`, then cut the section at the tag.
